# Windows 桌面客户端

AgentPulse 使用 Rust + GPUI，Windows 用户只启动一个 Tray 程序。Hub（权威会话与已读服务）和 Relay（中继服务）继续部署在 Linux；需要采集 Windows 本机 Agent 时，Tray 自动释放并托管内置 Go Bridge。WSL Debian 的 Bridge 由 Debian 自行运行，使用独立主机指纹。

## 运行与交互

解压到可写目录，双击 `agent-pulse-tray.exe` 即驻留托盘。程序默认读取自身目录的 `tray.yaml`；首次缺少该文件时创建未连接服务的空配置，不自动打开设置。可将 `tray.example.yaml` 复制为 `tray.yaml` 后填写 Hub 地址；源码开发时示例位于 `config/`。默认配置定位不依赖启动工作目录：

```powershell
./agent-pulse-tray.exe
# 启动后直接显示会话列表
./agent-pulse-tray.exe --show
# 显式打开设置；使用其他配置时可加入 --config tray.local.yaml
./agent-pulse-tray.exe --settings
```

默认驻留托盘。托盘右键打开系统上下文菜单，最多显示 5 个活跃会话，每项只有最多 12 个可见字符的标题和状态；主机、Agent 和未读详情放在会话小窗中。标题按完整组合字符截断，不影响点击对应会话。菜单的实际宽度、字体和间距遵循 Windows 系统度量。

托盘左键或“打开会话列表”显示无框小窗，可切换“活跃 / 需关注 / 全部”。行内显示标题、来源主机与环境、Agent、状态和未读数量；小窗打开期间保持现有行顺序，新会话追加，重新打开时应用排序。方向键选择、Enter 打开详情、Tab 切换筛选、Esc 或点击外部关闭小窗。打开菜单或列表不会标记已读。

悬浮图标默认关闭，可在托盘菜单开启。图标置顶，拖到工作区四边后吸附，移开约 650 毫秒后收起并保留约 8 个逻辑像素；悬停约 150 毫秒后展开，动画约 180 毫秒。点击图标打开小窗，小窗打开时保持图标展开。“设置”可隐藏图标或重置位置。偏好保存在便携数据目录，异常屏幕布局会限制到可用工作区。

选择具体会话才打开可复用的大详情窗口。事件按时间倒序每批加载 30 条，显示本地时间、类型、标题和未读/已读/普通记录；最新一条与未读事件默认展开，已读事件默认收起；可以同时展开多条，底部可加载更早事件。这不是完整 Agent 对话。只有详情位于前台、未最小化且展开内容进入滚动可视范围时才累计阅读时间，累计可见 3 秒后自动标记已读；后台、折叠及分页外事件不计时。自动已读不会收起当前正文，重新打开详情时才重新应用默认展开规则。“本会话全部已读”是独立动作。

设置和详情保留 Windows 原生标题栏及唯一一组窗口按钮，不重复绘制页面关闭按钮。详情允许调整大小和最大化，最小尺寸为 520×360 个逻辑像素；长消息在内部滚动，底部历史加载操作保持可见。设置允许调整大小，最小为 400×320，取消最大化。悬浮图标、会话小窗和提醒卡片继续无框且尺寸由内容规则控制。

关闭窗口只隐藏，托盘“退出 AgentPulse”才退出应用。同一 Windows 交互登录会话只运行一个实例；不同路径、配置及开发演示也共享此限制。重复启动在读取第二份配置、状态或启动 Bridge 之前通知原实例显示列表并退出。

## 配置与会话管理

配置相对文件路径以配置文件所在目录为基准。令牌可用 `${env:变量名}` 引用环境变量。默认未读缓存位于 `data/state.json`，悬浮偏好位于 `data/desktop.json`，均相对于配置所在目录；默认即程序目录。显式指定 `state_file` 可覆盖缓存位置。目录不可写时明确报错，不静默改存用户目录。不要提交真实地址、凭据、对话或个人文件路径。

移动、备份时保留整个程序目录；升级时只替换可执行文件，保留 `tray.yaml` 和 `data/`。配置含令牌、状态含提醒正文，应保存在本人可控制的位置。从旧版本升级时，先退出程序并备份旧配置与 `%LOCALAPPDATA%/AgentPulse/`，将原 `state.json`、`desktop.json` 复制到便携目录的 `data/` 后再启动；旧文件不会自动删除或覆盖，不能遗漏尚未同步的已读记录。

Tray 配置只需填写 Hub 地址；Hub 令牌仅在服务要求鉴权时填写。需要采集本机 Agent 时，在设置页点击“配置并启用本机 Agent”。向导会打开单独的控制台，扫描当前 Windows 用户已安装且受支持的 Agent，并逐个询问启用、禁用或跳过；只有明确选择的 Agent 配置会被修改。完成后的报告保留在控制台，按 Enter 返回设置；随后退出并重新启动 Tray，内置 Bridge 才会启动。修改后的 Agent 配置可能还需由 Agent 重启或重新加载；Codex 等宿主也可能要求用户确认项目或命令信任。

首次配置时，Tray 会在便携目录 `data/bridge.yaml` 创建并复用稳定主机指纹，主机可读名称默认采用 Windows 主机名，Hub 地址和已有令牌从 `tray.yaml` 取得。已有 `data/bridge.yaml` 或用户显式配置的 `bridge_config` 均不会被首次配置覆盖。内置程序按版本释放到 `data/internal/`，通过 Windows Job Object 随 Tray 退出清理，不接管独立 Bridge。只查看远端会话时无需运行向导。

Bridge 仍使用内存待发队列，退出会丢失尚未交付的事件；已确认事件、客户端缓存和离线已读有各自的持久化保证。启用接入后进程列表中会看到内部辅助进程，产品只有一个用户启动入口。

详情“会话管理”提供归档/恢复、人工修正为待继续/已结束/已中断/未知，以及恢复自动跟随。保留来源状态并显示修正时间；归档不删除历史、不停止 Agent、不自动已读。新有效活动解除人工覆盖，较旧原生序号或标记为历史的补报不会解除。无序号实时事件沿用到达顺序，来源不得把无可靠顺序的历史补报伪装成实时事件。

人工修正为结束/中断使先前等待提醒失效，但保留未读事实，不伪造完成事件或手机通知。管理动作须收到 Hub 的 HTTP 200 才确认，离线不排队；会话已变化时拒绝旧版本操作，刷新后再处理。离线已读继续支持持久暂存。

Bridge 主机指纹在首次 setup 时生成并保存在配置中，Tray 客户端指纹独立生成并保存在状态文件中；软件不提供修改指纹的功能。二者均支持配置 `host_name`，省略时采用系统主机名。Hub 主机管理页可集中覆盖显示名，所有 Tray 同步展示该名称，清空覆盖名称后回退为设备配置的名称。归档主机的会话和时间线在 Tray 中隐藏，Hub 保留历史；Bridge 再次上线会自动解除归档。原生标题通过事件的 `session_title` 提供，缺省使用项目或会话标识，普通通知标题不再覆盖会话标题。

升级时先备份 Hub 数据库并更新 Hub、Relay，再更新 Bridge/Tray 和 OpenCode 适配包。主机管理需要当前 Hub；数据库版本为 5，旧程序不能直接读取新库。回退须使用升级前备份，不能仅换回旧可执行程序。

## 中继发现与主机偏好

Tray 0.5.0 与 Bridge 均可从 Hub 直接取得 Relay 地址和令牌，省略 `relay_url`、`relay_token` 即启用自动发现。首次必须能直连升级后的 Hub；之后按 Hub 地址缓存，直连失败可使用缓存回退。重连时刷新，Hub 明确返回空配置时移除自动中继；查询失败保留缓存。手动配置优先，旧 Hub 仍可手动配置。

发现接口沿用 Hub 鉴权：配置了 Hub 令牌就必须提供，可信内网的无令牌 Hub 仍可使用。缓存包含中继凭据，应和 `tray.yaml` 一并妥善保管；它不会写入事件快照，也不经 Relay 分发。Hub 不在可信内网时按部署说明启用鉴权与 TLS。

设置页“主机提醒与唤醒”按来源列出已知主机，偏好保存在 `data/hosts.json`，可独立选择：

- **静默**：停止此客户端对该主机的主动通知、弹出和图标强调，继续接收记录、显示未读与状态。适用于已有其他推送的 Windows Agent。解除静默后不补弹此前已消费的提醒。
- **任务唤醒**：可选多个主机，包括 WSL Debian 来源。只要其中有在线、状态为“进行中”的任务，就请求 Windows 保持系统运行；等待输入/批准、完成、失败、人工修正为非运行状态、来源离线或 Tray 失联时释放。屏幕仍可熄灭，不改电源计划，也不阻止主动睡眠。退出程序自动释放。

保持唤醒依赖来源准确上报状态和心跳，断线按现有心跳超时识别。若 Agent 异常退出而未上报，仍在线的 Bridge 不能证明任务已结束，可在详情人工修正状态。归档只收纳列表，不会停止运行任务或唤醒请求。

## 登录自动启动

设置页的“开机自动启动”实际指当前用户登录 Windows 后运行。启用时在当前用户的“启动”文件夹创建 `AgentPulse.lnk`，目标指向当前程序并使用 `--autostart`，默认驻留托盘；已运行时登录启动不会再次唤起窗口。关闭时只移除这个快捷方式，不修改其他启动项，不写注册表。

用户也可在文件资源管理器地址栏输入 `shell:startup`，自行删除 `AgentPulse.lnk`。设置页打开时及显示期间重新读取快捷方式的实际目标、参数和 Windows 禁用状态，不在软件配置中保存启用布尔值。配置丢失不会隐藏系统中残留的快捷方式；程序移动后提示旧位置，可更新为当前位置或移除。

若 Windows“启动应用”已禁用此快捷方式，界面显示“被系统禁用”并提供打开系统设置的入口，不绕过用户的系统禁用选择。禁用信息采用只读兼容检查，未知格式或读取失败显示“无法确认”。仅管理本软件约定名称的当前用户快捷方式，不扫描或修改用户另建的计划任务、全局启动项和改名快捷方式。

Windows 启动文件夹用法见 [微软说明](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows)。删除整个便携目录前先关闭自动启动，或手动删除该快捷方式，避免留在系统中。

## 提醒与恢复

- 正常桌面新提醒更新未读角标。悬浮图标关闭时发送 Windows 系统通知；图标贴边收起时自动露出并强调约 7 秒，已显示时以琥珀色边框和背景短时强调，随后恢复。均不抢焦点、不自动打开列表或详情；系统通知点击后进入“需关注”。系统接口拒绝时回退摘要卡片。通知关闭或超时不等于已读。
- 离线已读先写本地状态。落盘失败保留未读并显示错误，成功后在本机隐藏，等待重连。
- 重连先补交已读，再获取订阅建立后的完整快照。Relay 202 只代表中继暂存，直到 Hub 200 才清理本地待同步记录。
- 在系统接受通知请求或悬浮提示交付后，才保存本机已提醒的事件 ID；交付与保存之间崩溃可能重复提醒，未读记录不丢失。系统免打扰和通知权限仍由 Windows 决定，接受请求不代表用户已阅读。失效未读可查看，不重复主动提醒。
- 锁屏、全屏及桌面状态未知时抑制卡片，桌面状态按周期读取；睡眠唤醒、远程桌面和真实全屏体验仍需原生验收。
- 缓存损坏保留原文件并报错，不自动清空未确认的已读。状态文件含提醒正文，应放在当前用户可控制的本地目录。

## Windows 窗口手工验收要点

可先启动下文构建的 `--demo` 演示版。演示版不连接服务、不读取或写入正式状态，可检查托盘菜单、会话列表、详情、长消息滚动和窗口大小。需检查主机同步、静默/唤醒和通知时，使用隔离 Hub 与合成事件；不要使用真实会话正文做截图或提交测试材料。

1. **启动和单实例**：正式版双击后只驻留托盘，不自动打开设置或会话窗口；重复启动只激活现有实例。关闭设置/详情只隐藏窗口，托盘“退出”才结束程序。
2. **托盘右键菜单**：右键托盘图标显示紧凑 Windows 菜单，而非直接打开主界面。最多显示 5 个活跃会话；标题最多 12 个可见字符，并显示状态。菜单应明显小于会话小窗。
3. **会话小窗**：左键托盘图标或选择“打开会话列表”才打开小窗。检查标题、主机显示名、Agent、状态和未读数量；切换筛选并打开会话，确认浏览列表本身不会标记未读。
4. **详情时间线**：最新事件和未读默认展开、已读默认收起，可同时展开多条。向下滚动后确认正文不会因标记已读而收起或跳动。展开内容在前台可见累计约 3 秒才标记已读；切走、最小化或滚出视口时不计时。
5. **缩放和滚动**：调整详情大小，检查长正文换行和上下滚动，底部加载旧事件操作保持可用；最大化后还原，内容仍正常。设置可调大小且无最大化按钮，原生标题栏只保留一组关闭按钮。
6. **主机快捷偏好**：在详情切换主机静默和任务唤醒，确认重启后偏好仍在；静默后记录和未读仍可查看。任务唤醒会阻止系统自动睡眠，测试前确认可让设备保持运行；结束后退出 Tray 并确认唤醒释放。
7. **通知分流**：用隔离服务制造未读，分别检查悬浮图标关闭时的系统通知、图标贴边收起时的露出，以及图标展开时的短时强调。强调不应抢焦点；通知本身不代表已读。
8. **悬浮图标**：检查开关、置顶、拖到屏幕边缘、收起后露出、鼠标移开后再次收起；托盘菜单关闭后应即时隐藏。多屏或 DPI 变化仅在条件具备时测试，否则记为未验收。
9. **主机管理**：在 Hub 修改显示名，确认各 Tray 都更新；归档后 Tray 隐藏会话，Hub 仍可查看历史；Bridge 重连解除归档。永久删除仅使用测试主机，并检查旧指纹无法重新登记。
10. **本机 Agent 配置入口**：只在隔离/可恢复的 Agent 配置上检查向导。确认它只列出已检测或先前由本 Bridge 管理的 Agent，逐项提供启用/禁用/跳过选项，并在报告中列出实际修改的文件；报告应等待按 Enter 后关闭。

按编号记录“通过 / 失败 / 未验收”。失败时只记脱敏后的现象，不提供会话正文、主机指纹或真实服务地址。

## 开发、演示与打包

以下命令从源码仓库根目录执行，需要 Rustup、MSVC、Windows SDK 和 Go，工具链由仓库文件固定：

```powershell
# 默认仅构建用户入口；内部 Bridge 不作为顶层程序分发
./scripts/build.ps1
./bin/agent-pulse-tray.exe --config config/tray.local.yaml --show

# 显式生成开发测试工具到 bin/dev
./scripts/build.ps1 -DevelopmentTools
./scripts/check.ps1 -Tray -Integration

# 前台控制台演示，Ctrl+C 退出
./scripts/build.ps1 -Demo
./bin/dev/agent-pulse-tray-demo.exe --demo
# 仅验收时显式打开演示设置
./bin/dev/agent-pulse-tray-demo.exe --demo --settings

./scripts/package-windows.ps1
```

演示由 `dev-demo` 编译开关和 `preview` 开发配置生成，与正式版一样默认驻留托盘。通过托盘“设置”或 `--settings` 打开演示操作入口。使用内存样例，不读取生产配置、不创建生产状态、不连接服务或启动 Bridge，不登记自启动，窗口命令输出到当前控制台。发布版编译排除演示代码和数据，`--demo` 返回非零退出码；发布配置启用演示开关会编译失败。

开发设置页可滚动到底部，检查长消息滚动、同一个原生托盘菜单、示例会话详情、浅深色配色及对应当前悬浮状态的通知；切换演示配色只影响本次演示，不改变 Windows 主题。示例事件已读后仍可刷新查看历史。

打包输出 `dist/windows-amd64/` 和同名 ZIP，只有 `agent-pulse-tray.exe`、两份示例配置和使用说明；首次运行创建自己的配置和数据。当前为免安装便携包，自启动由用户在设置中选择开启，没有系统安装、签名发布或客户端自动更新。搜索、主机/Agent 高级筛选、置顶和别名编辑界面尚未纳入首轮管理交互。

## Windows 适配包

`scripts/package-adapters.ps1` 生成 `dist/repository-windows/` 的 Windows amd64 命令包、通用 OpenCode 包和未签名索引。发布者仍需签名后分发。Codex、Qoder、Antigravity 包最低 Bridge 0.3.0，OpenCode 0.3.0 包最低 Bridge 0.4.0；ZCode 0.1.0 包需要 Bridge 0.5.0（Tray 0.5.0 已内置）。发布含 ZCode 的索引前，所有消费该索引的 Bridge 均须升级到 0.5.0，旧版不识别新增的进程钩子配置格式。先更新 Hub/Relay，再更新 Bridge/Tray，最后发布新索引。

安装器使用系统锁、临时文件同步替换与不可变包目录，保留用户其他配置，更新不覆盖正在执行的包。ZCode 3.17.2 已通过无项目任务、GLM-5.3-Flash 与内置 Bridge 的实际链路测试，接入方法及异常退出限制见 [适配器说明](adapters.md)。真实 Codex、Qoder、Antigravity 和 OpenCode 的 Windows 宿主加载与 hook 信任仍需逐一验收，构建成功不等于日常 Agent 已接入。

交互规则见源码文档 `docs/windows-desktop-design.md`；自动检查、原生验收摘要及待验收项见 `docs/development-status.md`。设计预览和自动化测试不能代替真实桌面的视觉、多屏、焦点与长期使用验收。
