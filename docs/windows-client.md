# Windows 桌面客户端

AgentPulse 使用 Rust + GPUI，Windows 用户只启动一个 Tray 程序。Hub（权威会话与已读服务）和 Relay（中继服务）继续部署在 Linux；需要采集 Windows 本机 Agent 时，Tray 自动释放并托管内置 Go Bridge。WSL Debian 的 Bridge 由 Debian 自行运行，使用不同来源标识。

## 运行与交互

解压到可写目录，双击 `agent-pulse-tray.exe` 即驻留托盘。程序默认读取自身目录的 `tray.yaml`；首次缺少该文件时创建未连接服务的空配置，不自动打开设置。可将 `tray.example.yaml` 复制为 `tray.yaml` 后填写 Hub 地址；源码开发时示例位于 `config/`。默认配置定位不依赖启动工作目录：

```powershell
./agent-pulse-tray.exe
# 启动后直接显示会话列表
./agent-pulse-tray.exe --show
# 显式打开设置；使用其他配置时可加入 --config tray.local.yaml
./agent-pulse-tray.exe --settings
```

默认驻留托盘。托盘右键打开系统上下文菜单，最多显示 5 个活跃会话，每项只有最多 12 个可见字符的标题和状态；主机、Agent 和未读详情放在会话小窗中。标题按完整组合字符截断，不影响点击对应会话。菜单的实际宽度、字体和间距遵循 Windows 系统度量。

托盘左键或“打开会话列表”显示无框小窗，可切换“活跃 / 需关注 / 全部”。行内显示标题、来源主机与环境、Agent、状态和未读数量；小窗打开期间保持现有行顺序，新会话追加，重新打开时应用排序。方向键选择、Enter 打开详情、Tab 切换筛选、Esc 或点击外部关闭小窗。打开菜单或列表不会标记已读。

悬浮图标默认关闭，可在托盘菜单开启。图标置顶，拖到工作区四边后吸附，移开约 650 毫秒后收起并保留约 8 个逻辑像素；悬停约 150 毫秒后展开，动画约 180 毫秒。点击图标打开小窗，小窗打开时保持图标展开。“设置”可隐藏图标或重置位置。偏好保存在便携数据目录，异常屏幕布局会限制到可用工作区。

选择具体会话才打开可复用的大详情窗口。详情按会话读取已采集的通知事件，每批 30 条，用上一条/下一条查看并可加载更早事件；不是完整 Agent 对话。只有详情位于前台且当前事件标题完整进入滚动可视区域时才自动标记已读，后台窗口、尚未滚动到的内容和分页外事件不自动已读。“本会话全部已读”是独立动作。

设置和详情保留 Windows 原生标题栏及唯一一组窗口按钮，不重复绘制页面关闭按钮。详情允许调整大小和最大化，最小尺寸为 520×360 个逻辑像素；长消息在内部滚动，底部翻页操作保持可见。设置允许调整大小，最小为 400×320，取消最大化。悬浮图标、会话小窗和提醒卡片继续无框且尺寸由内容规则控制。

关闭窗口只隐藏，托盘“退出 AgentPulse”才退出应用。同一 Windows 交互登录会话只运行一个实例；不同路径、配置及开发演示也共享此限制。重复启动在读取第二份配置、状态或启动 Bridge 之前通知原实例显示列表并退出。

## 配置与会话管理

配置相对文件路径以配置文件所在目录为基准。令牌可用 `${env:变量名}` 引用环境变量。默认未读缓存位于 `data/state.json`，悬浮偏好位于 `data/desktop.json`，均相对于配置所在目录；默认即程序目录。显式指定 `state_file` 可覆盖缓存位置。目录不可写时明确报错，不静默改存用户目录。不要提交真实地址、凭据、对话或个人文件路径。

移动、备份时保留整个程序目录；升级时只替换可执行文件，保留 `tray.yaml` 和 `data/`。配置含令牌、状态含提醒正文，应保存在本人可控制的位置。从旧版本升级时，先退出程序并备份旧配置与 `%LOCALAPPDATA%/AgentPulse/`，将原 `state.json`、`desktop.json` 复制到便携目录的 `data/` 后再启动；旧文件不会自动删除或覆盖，不能遗漏尚未同步的已读记录。

需要本机接入时设置 `bridge_enabled: true`，将 `bridge_config` 指向自己的 Bridge 配置，例如同目录的 `bridge.local.yaml`。不再配置 Bridge 可执行路径。内部程序按版本释放到便携目录的 `data/internal/`，通过 Windows Job Object 随父进程退出清理，不接管独立 Bridge。只查看远端会话时保持 `bridge_enabled: false`。

Bridge 仍使用内存待发队列，退出会丢失尚未交付的事件；已确认事件、客户端缓存和离线已读有各自的持久化保证。启用接入后进程列表中会看到内部辅助进程，产品只有一个用户启动入口。

详情“会话管理”提供归档/恢复、人工修正为待继续/已结束/已中断/未知，以及恢复自动跟随。保留来源状态并显示修正时间；归档不删除历史、不停止 Agent、不自动已读。新有效活动解除人工覆盖，较旧原生序号或标记为历史的补报不会解除。无序号实时事件沿用到达顺序，来源不得把无可靠顺序的历史补报伪装成实时事件。

人工修正为结束/中断使先前等待提醒失效，但保留未读事实，不伪造完成事件或手机通知。管理动作须收到 Hub 的 HTTP 200 才确认，离线不排队；会话已变化时拒绝旧版本操作，刷新后再处理。离线已读继续支持持久暂存。

主机名称与环境标签由 Hub 的 `sources` 配置提供，未配置则显示来源标识。原生标题通过事件的 `session_title` 提供，缺省使用项目或会话标识，普通通知标题不再覆盖会话标题。

升级时先备份 Hub 数据库并更新 Hub、Relay，再更新 Bridge/Tray 和 OpenCode 适配包。会话管理需要本轮服务端；Hub 首次启动迁移到数据库版本 3，旧程序不能直接读取新库。回退须使用升级前备份，不能仅换回旧可执行程序。

## 登录自动启动

设置页的“开机自动启动”实际指当前用户登录 Windows 后运行。启用时在当前用户的“启动”文件夹创建 `AgentPulse.lnk`，目标指向当前程序并使用 `--autostart`，默认驻留托盘；已运行时登录启动不会再次唤起窗口。关闭时只移除这个快捷方式，不修改其他启动项，不写注册表。

用户也可在文件资源管理器地址栏输入 `shell:startup`，自行删除 `AgentPulse.lnk`。设置页打开时及显示期间重新读取快捷方式的实际目标、参数和 Windows 禁用状态，不在软件配置中保存启用布尔值。配置丢失不会隐藏系统中残留的快捷方式；程序移动后提示旧位置，可更新为当前位置或移除。

若 Windows“启动应用”已禁用此快捷方式，界面显示“被系统禁用”并提供打开系统设置的入口，不绕过用户的系统禁用选择。禁用信息采用只读兼容检查，未知格式或读取失败显示“无法确认”。仅管理本软件约定名称的当前用户快捷方式，不扫描或修改用户另建的计划任务、全局启动项和改名快捷方式。

Windows 启动文件夹用法见 [微软说明](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows)。删除整个便携目录前先关闭自动启动，或手动删除该快捷方式，避免留在系统中。

## 提醒与恢复

- 正常桌面新提醒更新角标并显示短时摘要，不自动打开列表或详情；多个会话合并摘要，点击后进入“需关注”。卡片关闭或超时不等于已读。
- 离线已读先写本地状态。落盘失败保留未读并显示错误，成功后在本机隐藏，等待重连。
- 重连先补交已读，再获取订阅建立后的完整快照。Relay 202 只代表中继暂存，直到 Hub 200 才清理本地待同步记录。
- 自动提醒前保存本机已提醒的事件 ID；保存后、显示前崩溃可能漏一次弹出，未读列表仍保留事件。失效未读可查看，不重复主动提醒。
- 锁屏、全屏及桌面状态未知时抑制卡片，桌面状态按周期读取；睡眠唤醒、远程桌面和真实全屏体验仍需原生验收。
- 缓存损坏保留原文件并报错，不自动清空未确认的已读。状态文件含提醒正文，应放在当前用户可控制的本地目录。

## 开发、演示与打包

以下命令从源码仓库根目录执行，需要 Rustup、MSVC、Windows SDK 和 Go，工具链由仓库文件固定：

```powershell
# 默认仅构建用户入口；内部 Bridge 不作为顶层程序分发
./scripts/build.ps1
./bin/agent-pulse-tray.exe --config config/tray.local.yaml --show

# 显式生成开发测试工具到 bin/dev
./scripts/build.ps1 -DevelopmentTools
./scripts/check.ps1 -Tray -Integration

# 前台控制台演示，Ctrl+C 退出
./scripts/build.ps1 -Demo
./bin/dev/agent-pulse-tray-demo.exe --demo
# 仅验收时显式打开演示设置
./bin/dev/agent-pulse-tray-demo.exe --demo --settings

./scripts/package-windows.ps1
```

演示由 `dev-demo` 编译开关和 `preview` 开发配置生成，与正式版一样默认驻留托盘。通过托盘“设置”或 `--settings` 打开演示操作入口。使用内存样例，不读取生产配置、不创建生产状态、不连接服务或启动 Bridge，不登记自启动，窗口命令输出到当前控制台。发布版编译排除演示代码和数据，`--demo` 返回非零退出码；发布配置启用演示开关会编译失败。

开发设置页可滚动到底部，检查长消息滚动、同一个原生托盘菜单、示例会话详情、浅深色配色和提醒卡片；切换演示配色只影响本次演示，不改变 Windows 主题。示例事件已读后仍可刷新查看历史。

打包输出 `dist/windows-amd64/` 和同名 ZIP，只有 `agent-pulse-tray.exe`、两份示例配置和使用说明；首次运行创建自己的配置和数据。当前为免安装便携包，自启动由用户在设置中选择开启，没有系统安装、签名发布或客户端自动更新。搜索、主机/Agent 高级筛选、置顶和别名编辑界面尚未纳入首轮管理交互。

## Windows 适配包

`scripts/package-adapters.ps1` 生成 `dist/repository-windows/` 的 Windows amd64 命令包、通用 OpenCode 包和未签名索引。发布者仍需签名后分发。Windows 命令包最低 Bridge 0.3.0；含原生会话标题的 OpenCode 0.3.0 包最低 Bridge 0.4.0，并须先更新 Hub/Relay。

安装器使用系统锁、临时文件同步替换与不可变包目录，保留用户其他配置，更新不覆盖正在执行的包。真实 Codex、Qoder、Antigravity 和 OpenCode 的 Windows 宿主加载与 hook 信任仍需逐一验收，构建成功不等于日常 Agent 已接入。

交互规则见源码文档 `docs/windows-desktop-design.md`；自动检查、原生验收摘要及待验收项见 `docs/development-status.md`。设计预览和自动化测试不能代替真实桌面的视觉、多屏、焦点与长期使用验收。
