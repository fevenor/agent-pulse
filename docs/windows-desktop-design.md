# Windows 桌面交互设计与 GPUI 可行性

## 状态与用途

本文维护用户已确认的 Windows 桌面交互规则与技术边界。当前运行方法见 [客户端说明](windows-client.md)，实现进度、自动检查和原生待验收项见 [开发记录](development-status.md)。临时设计预览保存在本地 `tmp/design/`，不随源码分发；浏览器预览不代表 Windows 原生交互已验收。

## 1. 产品入口、构建与运行

### 面向用户只提供 Tray

Windows 用户只启动 AgentPulse Tray。Hub 与 Relay 继续部署在 Linux Docker；测试客户端、发布工具和推送探针不进入 Windows 用户包。默认 `scripts/build.ps1` 只将用户入口放入 `bin/`；显式开发工具构建输出到 `bin/dev/`。

交付一个用户可运行的 Tray 程序，按需内置已有 Go Bridge（本机 Agent 事件接入能力），由 Tray 自动释放到便携目录的 `data/internal/` 版本化内部目录并管理。只查看远端会话时不启动本地 Bridge；启用 Windows Agent 接入时才运行辅助进程。用户无须单独下载、配置可执行路径或启动 Bridge。WSL 内的 Bridge 仍跟随 Debian 环境运行。

这是“一个用户入口、一个发行产品”，启用本机接入后进程管理器仍能看到内部 Go 辅助进程。保留经过验证的 Go 实现，避免为收敛入口而重写接入链路。

默认 Windows 构建只生成 Tray 交付所需部分；测试服务和发布工具由明确的开发构建入口生成到独立目录。可执行适配包仍按已有签名更新机制管理，不因为只交付 Tray 就取消本机 Agent 接入。

### 便携配置、启动与窗口

普通启动和开发演示均默认驻留托盘；只有显式 `--show` 或 `--settings` 打开列表或设置。默认读取程序旁的 `tray.yaml`，首次缺失时创建空配置；缓存、悬浮偏好及内部辅助程序保存在旁边的 `data/`。指定其他配置时，相对路径和数据目录跟随该配置所在目录。目录不可写时明确报错，不静默回退到用户目录。升级保留配置和数据，旧版缓存迁移说明见客户端文档。

登录自启动使用当前用户“启动”文件夹的 `AgentPulse.lnk`，设置页读取快捷方式的目标和参数以及 Windows 禁用状态，不保存自启动布尔值。用户可从 `shell:startup` 手动删除；软件关闭自启动也只删除该快捷方式。移动程序后识别旧位置，允许更新或移除。系统禁用时提示在 Windows 启动应用中恢复，程序不写注册表，不自动撤销禁用，不管理其他命名的快捷方式或计划任务。`--autostart` 即使遇到已有实例也不唤起窗口。

设置和详情保留 Windows 原生标题栏，页面不重复显示关闭按钮。详情可调整尺寸和最大化，最小 520×360 个逻辑像素，正文独立滚动、底部翻页固定；设置可调整尺寸，最小 400×320，禁用最大化。悬浮图标、会话小窗和提醒继续无框，不扩大为完整主窗口。

### 单实例

单实例范围为当前 Windows 用户的交互登录会话。不同安装路径、不同配置文件、正常模式及开发演示都共享同一个应用实例锁。不同 Windows 用户或独立远程桌面登录会话各自拥有桌面，不互相弹窗。

在创建窗口、读取/修改状态及启动 Bridge 之前取得命名互斥锁。第二次启动只向已有实例发送“显示会话列表”的固定激活消息后退出，不创建第二个托盘图标，不重启 Bridge，不把第二份配置静默切换进去。若开发模式已占用实例，控制台说明后退出。现有状态文件锁继续保护数据，但不再承担产品单实例职责。

### 演示仅用于开发

开发构建显式启用演示能力，`--demo` 在当前控制台前台运行，持续输出窗口、状态转换和模拟事件日志，Ctrl+C 正常退出并释放锁。开发演示使用内存示例，不读生产配置、连接服务或启动 Bridge。

发布构建在编译阶段排除演示数据、演示控件及参数入口，而非仅隐藏按钮。独立的开发 feature（Cargo 编译开关）配合开发 profile；发布打包检测不得启用该开关。发布程序遇到 `--demo` 按不支持的参数退出，不进入模拟模式。正常发布运行保持无控制台窗口，连接和运行错误在设置或提示中说明；不记录凭据和会话正文。

## 2. 三层交互

| 层级 | 入口和职责 | 表现 |
| --- | --- | --- |
| 常驻入口 | 系统托盘、可选悬浮图标 | 无主窗口；托盘右键打开上下文菜单，提供会话快捷项及应用操作 |
| 会话小窗 | 点击悬浮图标，或明确选择“打开会话列表” | 无框紧凑列表，快速判断哪台主机的哪个会话需要关注 |
| 会话详情 | 点击具体会话行 | 才打开较大窗口，显示该会话摘要、事件时间线和管理操作 |

托盘右键采用用户指定的类似 ChatGPT 桌面端的上下文菜单形式：紧凑菜单项、分组分隔线、勾选项及菜单交互。它与带筛选和双行信息的会话小窗是两个独立界面，右键本身不打开列表窗口。参考的是菜单形式，不要求复制 ChatGPT 的具体功能或逐像素外观。

菜单宽约 260 个逻辑像素，普通行高约 28；会话区最多 5 项，菜单总高度在 5 项时约 310，随会话数减少而收短。Windows 系统缩放及原生菜单度量优先，不强行缩小系统字号。会话区仅展示活跃会话，沿用下文“未归档、未结束”的活跃口径；不会仅因存在未读而纳入已结束或已归档会话。

菜单排列：“活跃会话”分组标签、最多 5 个会话快捷项、分隔线、“打开会话列表”、“显示悬浮图标”勾选项、“设置…”、分隔线、“退出 AgentPulse”。不增加会话统计或未读摘要行；重置悬浮位置放入设置。超过 5 项时，“打开会话列表”显示为“查看全部活跃会话（数量）”，进入小窗的活跃筛选；菜单自身不展开长列表。空列表显示不可操作的“暂无活跃会话”；连接中断时将分组标签改为“活跃会话 · 离线”，不额外占一行。

会话项仅显示“短标题 + 状态”，不展示主机、环境、Agent 名称或未读。标题最多 12 个可见字符，超长时显示前 11 个字符和省略号；按完整可见字符边界截断，不拆开组合字符或表情。标题区域宽度仍有限制，遇到宽字符以像素宽度进一步截断，状态保留完整文字。完整标题和主机在小窗及详情查看；不同会话即使截断后同名也通过稳定会话标识绑定，不把标题当作点击目标的身份。

状态与未读只保留一个时，状态：它直接区分“进行中、等待批准、待继续、执行失败”，能够判断是否要介入；未读只表示是否看过某条事件，阅读后消失也不代表任务已恢复。菜单不以点、数字或加粗再次叠加未读，未读继续通过托盘/悬浮角标、小窗筛选和详情呈现。该精简只影响菜单信息密度，不改变提醒与已读规则。

点击会话项直接打开对应详情；仅展开菜单不标记已读。悬浮开关使用菜单勾选状态，不在菜单里嵌入表单或列表筛选。选择命令后收起菜单；点击外部、Esc、方向键和 Enter 遵循标准菜单行为。展开期间固定会话项与标识映射，下一次展开应用新的排序，防止动态更新让点击目标换位。

实现优先复用 `tray-icon::menu` 已有的 Windows 原生菜单能力（底层为 muda），以普通菜单项、勾选项和分隔线完成上述结构。GPUI 绘制悬浮图标、会话小窗和详情；不为托盘右键复用完整会话小窗。HTML 预览只模拟菜单结构，真实主题、尺寸及键盘行为以 Windows 原生验收为准。

同一时刻只有一个会话小窗、一个可复用的详情窗口；不同会话点击切换内容，不累积窗口。托盘左键打开列表，右键只展开菜单；键盘激活可到达相应入口。

### 2.1 会话小窗

宽 360 个逻辑像素，行高约 64，最多直接展示 6 行，再滚动；高度随内容变化，上限 480，不固定留大块空白。用户系统缩放会影响物理像素大小。浮窗从入口附近向可用屏幕区域展开，始终避开任务栏并留 8–12 个逻辑像素间距。

每行信息：第一行会话标题和状态；第二行主机别名、运行环境、Agent；右侧用点或数量标识需要关注的未读。主机名缺失时用来源标识原文，不能猜测真实电脑名称。标题优先使用原生会话标题，缺失时显示项目或明确的会话缩略标识，不把最后一次事件标题当作永久会话标题。

上方仅保留产品名、连接状态和“需关注 / 活跃 / 全部”筛选。活跃包括进行中、等待输入/批准、待继续、失败、中断及未知但尚未归档的会话；已关闭且无未读的会话留在“全部”。失败会话不会因为不再运行而从入口消失。只有已关闭但仍有未读的会话也要能从“需关注”找到。

排序：等待用户、失败/中断/未知中的未读、其他未读、正常活跃；组内按最近活动排序。用户正在悬停或键盘选择时延后重排，避免点击目标跳动。状态与未读更新可立即显示。

点击行外部或按 Esc 关闭小窗。小窗内按钮操作、滚动、打开二级菜单不触发关闭。Tab/方向键/Enter 可操作，焦点样式清晰。打开列表或悬停不标记已读。

### 2.2 悬浮图标和贴边

默认只驻留托盘；用户在托盘右键菜单中勾选“显示悬浮图标”后，首次出现在主屏右下角工作区，随后记住显示器、位置和收起边缘。

图标 44×44 个逻辑像素，使用简洁脉冲标识；未读需要关注时显示数量角标。常驻图标保持置顶，悬停可显示简短数量提示，不持续闪烁。不显示数据库、连接重试次数或 Bridge 技术信息。

| 状态 | 行为 |
| --- | --- |
| 自由放置 | 拖动图标移动；移动超过 5 个逻辑像素判定拖动，不误触点击 |
| 靠近边缘 | 释放时距离边缘不超过 16 个逻辑像素则吸附；允许四边，角落选择最近边 |
| 收起 | 留 8×44 或 44×8 的可命中部分；视觉上图标藏入边缘，不能完全移出导致找不到 |
| 鼠标移入 | 在露出的部分停留约 150 毫秒，图标以约 180 毫秒滑回工作区，不打开列表、不激活键盘焦点 |
| 鼠标移出 | 离开图标与关联小窗区域约 650 毫秒后收起；回到区域取消计时 |
| 小窗展开 | 图标保持展开；鼠标从图标移向小窗时不误收起；关闭小窗后恢复计时 |
| 主动隐藏 | 托盘关闭悬浮开关后完全隐藏；重开恢复上次合法位置 |

多显示器接缝和任务栏侧不能简单把窗口移出边界：使用当前屏幕工作区与裁剪命中区域，避免图标跑到另一屏、覆盖任务栏或透明区域拦截鼠标。显示器拔出、DPI 改变和工作区变化后重新限制位置；从托盘“设置…”进入“重置悬浮位置”可恢复入口。原型先验证右边缘，再扩展四边及多屏。

动画只在显示/收起过程中驱动帧，静止时无持续动画循环。遵循系统减少动态效果设置。全屏时不自动展开小窗或详情；图标可作为小标识，独占全屏不可显示时延迟提醒，不强行退出全屏或抢焦点。

### 2.3 会话详情

初始约 760×560 个逻辑像素，可调整尺寸，普通窗口层级，用户主动点击才激活。标题区显示会话标题、Agent、主机/环境和实际状态；正文是当前提醒与这个会话的事件时间线，避免把所有会话事件混在一起。

目前采集的是通知事件，不是完整 Agent 对话。详情只能展示已采集的内容、时间、项目和来源信息；完整对话、工具输出、源码或远程控制不属于本轮目标。

成功加载并实际展示的未读事件才能标记已读：详情须位于前台，当前事件标题完整进入滚动可视区域；后台窗口、尚未滚动到的内容、分页外、加载失败和新到但未显示的内容不自动已读。显式“本会话全部已读”是独立动作。返回小窗保持原筛选与位置；关闭详情不退出应用。

## 3. 通知表现

需要关注与“当前正在运行”分开呈现：进行中为蓝色小标识、等待用户为琥珀色、失败为红色、待继续为中性色；每种状态同时显示文字，颜色不是唯一信息来源。

正常桌面收到新事件时更新托盘和悬浮角标，附一张不激活焦点的短时摘要卡片；卡片与入口错位，避免互相覆盖。不会自动弹出完整会话列表或大详情。点击摘要打开对应详情；超时收起不等于已读。全屏只更新标识，退出全屏后再按未读有效性恢复提醒。

自动摘要沿用已确认的主动提醒目标。多个会话同时到达合并成摘要，点击后打开“需关注”列表，不随便选择一个会话。

## 4. 会话管理和异常修正

### 状态的三种含义

- **来源状态**：Agent/Bridge 实际上报的进行中、等待、完成、失败等事实。
- **连接状态**：来源主机能否联通；断线只表示暂时无法确认，不等于任务失败，也不证明任务仍在运行。
- **人工管理状态**：用户的标题别名、归档和状态修正；与来源状态并存显示。

个人使用的管理范围：搜索和主机/Agent 筛选、置顶关注、标题别名、归档/恢复、标记已读，以及对明显过期的会话作人工修正。首轮先交付归档/恢复、已读及异常修正；搜索、主机/Agent 高级筛选、置顶、别名编辑、批量编辑与历史清理后置。归档只调整列表收纳，不删除历史、不停止 Agent、不自动已读。

人工修正默认只提供“待继续 / 已结束 / 已中断 / 未知”和“恢复自动跟随”。避免把尚未验证的任务人工标为“成功”。展示“手动修正”标识、原始状态、修正时间与可选备注。新到的有效来源活动自动恢复自动状态；迟到或历史事件不清除覆盖。修改时若会话已经收到新事件，提示刷新后重试，不能覆盖用户没看到的新状态。

修正为已结束/中断可使更早的等待输入/批准提醒失效；不删除未读事实，不生成伪造的 Agent 事件，不额外触发“任务完成”手机通知。尚未展示的失效提醒继续留在详情或“全部”，可明确标记已读。

管理动作保存到 Hub 并同步给其他客户端。离线时可继续使用已有离线已读；归档、别名和人工修正先不提供离线提交，避免额外引入一套冲突/重放机制。即使经过 Relay，也只有 Hub 真正提交才显示管理成功。

### 数据职责

| 需要解决的问题 | 最小规则 |
| --- | --- |
| 主机友好名称 | Hub 的 `sources` 配置名称和环境；缺失回退来源标识 |
| 稳定会话标题 | 可选 `session_title` 独立维护；人工别名保留来源事实 |
| 单会话详情 | 历史接口按完整会话键过滤后分页 |
| 状态时效判断 | 保留最近事件类型、时间与来源连接；断线不武断判失败 |
| 归档与人工修正 | Hub 持久保存少量管理字段，校验最近事件及管理版本，复用快照广播 |

不为此建设账号/角色、通用工作流、事件溯源平台或新的同步服务。

## 5. 视觉规范

风格为简洁的 Windows 桌面工具：中性底色、明确文字层级、紧凑行布局、细分隔线和适度圆角。浅色/深色随系统，预览两种主题均可切换；字体优先 Segoe UI Variable 与 Microsoft YaHei UI，正文约 13–14，二级信息约 12，标题约 16–20 个逻辑像素。普通列表不使用一排大色块和大按钮。

图标使用一致线条体系，来源名称直接用文本，未经核对不仿造官方商标。只有需要用户处理的状态用强调色；留白服务于信息分组。细边框和阴影用于区分悬浮窗口，不把整张桌面做成仪表盘。

会话小窗首屏回答三个问题：哪个会话、在哪台主机、现在需要做什么。托盘菜单进一步压缩为短标题和状态，便于快速查看及跳转。更多动作放在详情或明确的“更多”菜单中；技术诊断放在设置页。

## 6. GPUI 0.2.2 可行性评估

结论：继续使用现有 GPUI 有可行依据，当前没有必须更换框架的证据。GPUI 负责内容绘制、布局和元素交互，tray-icon 接收托盘事件，少量 Win32 函数负责桌面窗口行为。贴边动画、裁剪与跨屏行为是需要原生小原型验证的重点，不以浏览器预览代替通过结论。

| 能力 | 已查到的依据 | 判断及未完成验证 |
| --- | --- | --- |
| 托盘右键上下文菜单 | 现有 tray-icon 0.26.1 已通过 `with_menu` 使用 Windows 菜单；锁定 muda 0.21.2 支持增删菜单项、勾选项、分隔线及菜单事件 | 可扩展为活跃会话快捷项与悬浮开关；需验动态菜单更新时机、长标题、键盘入口、任务栏溢出区域及主题表现；不需要 GPUI 小窗替代菜单 |

## 7. 已确认的边界

- 一个用户入口，内部按需启动现有 Go Bridge 辅助进程。
- 悬浮入口默认关闭，由托盘开关开启并记忆位置。
- 人工覆盖保留来源事实；新有效活动恢复自动跟随。迟到的识别沿用可靠原生序号与历史标记，无序号实时流按到达顺序。
- 正常桌面的新提醒采用角标和短时摘要，全屏不弹大窗。
- 首轮管理交付归档/恢复、已读和异常修正；搜索、主机/Agent 高级筛选、置顶、别名编辑及批量历史清理后置。

实施进度与验收证据只维护在开发记录；本页规则不等于所有桌面场景已通过验收。
