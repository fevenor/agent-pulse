# 适配仓库更新与 Bridge 按需同步

本文维护当前更新规则；功能已进入`v0.6.0-rc.4`草稿并完成授权部署，尚未公开。实施与验证证据见[开发记录](development-status.md)。

## 目标与职责

普通新增 Agent、事件映射、宿主探测或 hook 配置更新，通过独立签名适配包交付，不要求重新部署 Hub/Bridge。新增操作系统运行方式或统一事件协议能力仍可能需要核心升级，不承诺任何未来系统能力都能仅靠包实现。

- 发布者：构建、验收并以既有私钥签名完整索引。私钥不进入 CI、Hub、Bridge 或归档。
- Hub：从独立 GitHub 发布或离线目录/ZIP 获取仓库，验签、保存所有目标平台的包，最后推广完整索引。不执行 adapter。
- Adapter：提供产品名称、默认路径、宿主探测、配置解析与修改内容，以及原生事件转换、身份核对与终态观察。
- Bridge：执行有界本机接口、展示来源和启用选择、校验包与用户授权文件，协调安装、恢复与本机采集。新来源不会因 Hub 发布包而自动启用。

现有标准包的内置探测与配置路径保留作离线基础目录和旧副本的维护入口；带控制入口的新包优先使用自身实现，新增来源不需要加入该基础名单。签名包以当前用户权限运行，接口职责不是安全沙箱，发布审核仍然必要。

## Hub 获取与推广

在线来源使用同一 GitHub 项目的独立 `adapters-<发布序号>` Release，不跟随产品 latest，不接收草稿或短期 CI Artifact。独立发布携带 `index.json`、各 `<sha256>.zip` 平台包和完整离线 ZIP；归档内容为 `index.json` 与 `packages/<sha256>.zip`。

日程默认每天 **02:00，Asia/Shanghai**，可调整每日时间、时区或关闭：

```yaml
adapter_directory: "/data/adapters"
adapter_seed_directory: "/repository" # 可选，只用于首次初始化
adapter_repository_updates:
  github_repository: "fevenor/agent-pulse"
  daily_at: "02:00"
  timezone: "Asia/Shanghai"
  disabled: false
```

服务启动不额外联网检查；下一次配置时刻检查，失败等待下一次日程，不频繁重试。管理员可立即执行：

```sh
agent-pulse-hub --config /配置/hub.yaml --update-adapters
agent-pulse-hub --config /配置/hub.yaml --import-adapters /已核验/adapter-repository.zip
# --import-adapters 同样接受已解包的仓库目录
```

管理员命令不打开业务数据库，可与 Hub 服务并行执行；在线、离线及初始种子共用仓库锁。没有免登录的上传或发布 API。

推广顺序：

1. 以固定公钥验签。旧序号拒绝；同序号同内容无变化，同序号不同内容拒绝。同 ID、版本与平台的内容及元数据不可修改，仓库保留不可变版本记录。
2. 所有平台包均保留，不按 Hub 自身 CPU 筛选。已校验的包不重下、不重写；缺少的包才从当前来源获取。
3. 校验大小、摘要、文件数、解压上限、普通文件、入口及路径安全；拒绝穿越、链接和特殊文件。Hub 不执行包。
4. 包全部准备完毕后，最后原子替换活动索引。失败保留旧活动索引及业务数据；准备好的孤立包不影响旧仓库。
5. 旧包不立即清理，保障在途下载。离线导入较高序号后，在线旧发布不能将其回退。回滚必须签署更高序号选择旧包。

固定公钥来自显式配置、既有本地公钥或可信镜像的首次种子；归档中的公钥不能替换信任。镜像 `/repository` 仅初始化一次，可写活动仓库放 `/data/adapters`，随数据卷保存。已有活动索引不被镜像覆盖，不要求因 adapter 更新重启 Hub。

## Bridge 检查时机与离线规则

| 场景 | 清单检查 | 本地应用 |
| --- | --- | --- |
| 每次启动 | 一次逻辑条件检查，不受最小间隔限制 | 为已授权来源更新或修复，IPC 和旧入口不等待下载 |
| setup | 达到最小间隔才检查 | 先刷新目录和缓存，仅修改本次明确选择的来源 |
| sync-adapters | 达到最小间隔才检查 | 应用已授权来源，不启用新来源 |
| 上述命令带 --force-sync | 绕过时间节流 | 不绕过验签、摘要、隔离或授权，不重下相同包 |
| 日常运行、重连、Hub 推广新包 | 不检查、不下载 | 保留正常转发、状态报告和终态观察 |

最小间隔默认 **300 秒**，配置为 `adapters.min_check_seconds`，最小 5 秒。最近尝试、成功时间和 Hub/公钥上下文保存在本地；失败尝试也参与节流，更换 Hub 或信任上下文不复用旧节流时间。一次逻辑同步可以包含必要的分块包下载和 Relay 回退。启动同步总预算两分钟，结束后不在运行中偷偷补查。

```sh
agent-pulse-bridge setup --config /配置/bridge.yaml --force-sync
agent-pulse-bridge sync-adapters --config /配置/bridge.yaml --force-sync
```

节流只限制清单检查，不限制可信缓存的本地安装或修复，也不阻止取得清单已指定的缺包。检查失败时 setup 继续使用可信清单和包副本；完全没有可信清单时可以保存基本配置和维护既有接入，不能凭空发现未知产品。选中来源缺少必需包、配置无效或实际写入失败时保存意向并报告接入未完成，不把告警或接口成功当安装完成。

本地保存已校验 ZIP；入口缺失时可以离线重解包。长时间不重启且不执行上述命令的 Bridge 不会取得新包；启动离线后也不会因重连自动更新。紧急修复需明确重启或手工同步。

## 随包控制接口与 hook 联动

签名 Manifest 的 `name` 提供名称，`control` 指向包内的本机可执行入口。Bridge 向它执行 `--control`，JSON 输入/输出限定为 2 MiB，单次五秒；固定操作为：

- `probe`：返回名称、宿主版本、绝对默认配置路径、必要的信任/外部管理提示。Bridge 先校验并下载包再执行。
- `configure`：接收用户明确授权的当前文件内容、Bridge 路径与连接信息、启用/停用意图，仅返回新内容。
- `verify`：核对已生成内容与宿主总开关。用户关闭开关时不能报告已完成接入。

契约定义见 `go/internal/adapters/control.go`。Bridge 只写用户授权的配置路径，控制回复不申请其他文件写入；包已经是以当前用户权限运行的受信代码，不把控制协议伪装成安全沙箱。产品配置格式与默认路径由包实现。OpenCode 与 DSH 的受管理包携带平台对应的 Go 控制程序，插件仍运行在宿主已有环境，目标不新增 Node/Python 或编译环境。

Hub 不执行 `ValidateRuntime`，不解释宿主命令、hook 名、配置格式与兼容范围；Bridge 有 `control` 即通过既有本机契约安装，无产品 kind 白名单。必要的签名、摘要、大小、包路径与文件归属检查留在分发/提交边界。数字宿主版本政策在本机安装时验证，不因单个本机不适用的包阻断整个仓库。

当前残余边界：无控制入口的标准包仍使用 Bridge 内置目录与配置逻辑；OpenCode 固定 loader 仍由 Bridge 生成。它们不是新插件的必经路径。DSH 已从内置目录、配置分支和 loader 中移出，只通过随包 `probe/configure/verify` 接入。

每 Agent 的包选择和 hook 配置作为一个应用单元：下载及生成内容持同步锁，短提交与 dispatch 选版共用另一把锁。保存恢复日志，固定包与配置后删除日志；崩溃恢复旧组合。提交前再次核对文件未被外部修改；中断后发现外部修改时拒绝覆盖，保留日志供人工处理。已选定旧包的调用继续执行旧包，后续调用只在提交完成后选新包。DSH 的宿主配置直接指向不可变包，包入口不读取未完成日志，安装恢复仅切回原配置；既有 OpenCode 固定 loader 仍有核心生成逻辑，属于后续可拆分的历史实现。

外部环境管理的hook只读保留，其本机adapter仍可在宿主兼容时独立更新；未完成日志恢复时不重复写入未变的外部hook。

即使 304、节流跳过或包相同，也核对并修复自有 hook；无变化不重写，用户其他 hook、配置及显式关闭开关保留。setup 初始刷新不升级全部来源，选择“保持不变”的来源不动。

文件更新不代表宿主热加载，结果提示需重新加载/重启；不杀宿主。身份核对、轮次去重和终态观察使用来源/会话/轮次信息，不要求新增 Agent 修改 Hub 数据库或事件格式。已安装版本和最近实际运行回执保持区分。

## 独立发布

先使用现有构建、合并和签名命令生成完整仓库，再准备离线包：

```sh
uv run --no-project python scripts/release/publish_adapter_repository.py \
  --repository /签名仓库 --public /可信/publisher.pub \
  --publisher /已构建/agent-pulse-adapters --output /输出/adapter-repository.zip
```

默认仅准备本地文件；使用`--draft --github owner/repository --commit <40位构建提交>`创建草稿，Hub不获取草稿。发布者明确追加 `--publish --github owner/repository --commit <40位构建提交>` 后才创建公开独立发布与标签。工具不覆盖既有发布，不修改产品 latest；发布之前应获得相应 Git/GitHub 写授权。未公开的本地包不能作为普通用户在线安装目标。

## 验证与扩展边界

必要验证覆盖在线/离线一致性、不可变版本、序号、坏包、锁、完整推广、日程配置、一次启动检查、重连不检查、未知 Agent 动态目录、升级与 hook 联动、离线 setup、保持不变和短提交选版。固定接口 fixture 不能代替真实宿主事件及手机提醒实收。

首次上线需要一次 Hub/Bridge 更新；Windows 内置 Bridge 随 Tray 分发，必须重新构建后部署。之后普通 adapter 发布不要求更新这两个核心程序。本实现不引入旧网络字段兼容、接收器门槛、存储迁移、任务调度服务或插件商城，不清空现有数据。
