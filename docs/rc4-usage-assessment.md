# RC4 使用反馈优化评估

实施范围确认日期：2026-11-19。已开始本地优化与修复；当前阅读/分页规则见[事件覆盖](event-coverage.md)，实施和验证状态见[开发记录](development-status.md)。候选目标为0.6.0-rc.1；Antigravity首次子会话漏入已在本机原生复现并修复，发布和部署状态以开发记录为准。沿用既有技术栈，不引入新服务或存储迁移。

## 术语

- **已读**：用户已看到或明确确认某条提醒，不代表完成事件正文已逐字阅读，也不代表任务已经处理。
- **失效提醒**：后续原生活动已使原来的提醒不再适合主动通知；它仍可能未读。失效与已读互不替代。
- **普通运行记录**：会话开始、恢复或模型/工具活动产生的无正文状态记录；用于维护运行状态，不属于需要用户关注的提醒。
- **关键事件视图**：默认历史查询方式，保留完成、等待输入/批准、失败、中断、状态不明及有意义正文，排除普通运行记录；完整历史仍可显式查看。

## 当前实施边界

- 前台展开、标题完整可见连续1.5秒自动已读，离开阅读条件后重新计时。
- 打开会话优先定位最近未读，提供下一条未读与回到最新；自动标读和新增事件不抢历史阅读位置。
- 默认关键事件先筛选再分页，完整活动按需查看；保留Hub全部原事件及运行状态。
- Antigravity正常停止且后台未空闲时保留运行，明确错误和取消分别处理，未知终止类型不猜成功。
- Antigravity身份结果区分明确主/子和暂不可确认，增加同次转换的按需私有诊断；明确App路径的元数据暂缺事件在Bridge本机有界等待身份核对，主会话按序转发、子任务过滤，不直接丢弃正常主会话。
- Agent内已读同步不实施，OpenCode也不单独接入。已有误入子会话不合并、删除或自动归档。

## 已读停留时间的依据与范围

1.5秒是本项目的交互建议，没有可靠依据把它称为统一行业标准，也不能说它能证明用户读完整段内容。本次能直接核实的产品例子是Thunderbird：Mozilla官方主线源码启用自动标读，默认关闭延迟；用户启用延迟后，该配置初值为5秒。因此，同一产品也同时提供即时与延迟两类方式，不能从中推导行业平均秒数。

上游依据为Mozilla官方仓库 `mailnews/mailnews.js`，`mailnews.mark_message_read.auto=true`、`mailnews.mark_message_read.delay=false`、`mailnews.mark_message_read.delay.interval=5`。源码获取于2026-11-19；主线配置不代表所有已发布或用户自定义安装的现状。本次未取得足够可靠的当前官方依据确认Slack/Outlook的具体规则，不将其写为已核实结论；当前Gmail官方预览说明也未给出固定标读秒数。

本项目采用前台展开、标题完整可见连续1.5秒；离开视口或失去阅读条件即重新计时。1.5秒服务于快速查看状态并减少一闪而过的误读，不用于估计阅读速度，也不引入按字数计算阅读时长或新的设置项。没有证据表明1.5秒相对1秒具有普适优势，最终需结合真实滚动和打开详情的使用感受验证。

## Agent 内已读同步

本轮不实施任何Agent的原生已读同步，OpenCode也不单独接入。原生已读观察、文件监听、读回执协议和双向同步均不进入实施范围。普通活动、恢复会话或发送下一条消息不自动代表用户阅读了既有提醒。保留Tray前台可见后自动已读与明确标读，并沿用现有跨客户端同步。

## 适配包更新与版本说明

三类版本相互独立：AgentPulse组件发行版本、AgentPulse适配包版本、被接入Agent本身的宿主版本。清单中的 `agent_min` / `agent_max` 是宿主兼容范围，不是宿主升级目标。

Bridge启动后检查Hub提供的签名索引，通常每300秒加0至59秒随机间隔复查；按平台、已启用来源、固定版本和宿主兼容条件选择包。签名、摘要、大小与安装检查通过后切换。Hub不可达时可经已配置Relay获取；同版本同摘要不重复下载。同版本不同内容拒绝安装，失败保留旧包。命令hook下次调用通过固定入口选择已安装包，插件需实际重新加载；目标、已安装、最近运行三个字段不能混同。

此机制只更新AgentPulse适配包，不升级Agent软件、不自动升级Bridge/Tray，也不会自行拉取新的Hub镜像。宿主版本栏是版本探测值：WSL Antigravity优先枚举当前用户 `~/.antigravity-server/bin/<版本>/language_server` 并取符合要求的最高安装版本；它不是逐次hook中实际执行进程的证明。核对宿主版本时应同时查看实际进程的可执行路径。

当前包版本由维护者更新manifest，使用数值主、次、补丁排序；同版本产物不可变、已分发不同内容必须使用新版本。文档没有把每个主次补丁增长原因完整规定为严格SemVer承诺。大量补丁来自共用Go转换入口变动、构建/打包内容变化和候选实际分发，并不代表Agent功能反复大升级。0.x仍处于正式1.0前，补丁数字没有到9就进位的限制。

版本流程的建议仍待确认：保持独立版本；功能不变且能复用原包时不重建、不涨号；把尚未分发的多次修复合并为一次发布；共享代码确实改变其他包字节时仍用新版本，不覆盖已分发内容，也不为降低数字而回退编号。

## 低流量 WSL 定位方式

目标机上的Codex与Antigravity均在WSL运行，诊断应在相同发行版和用户下执行。无需克隆整个仓库或安装Go、Rust、Node、Python及依赖；可将开发机离线编译的独立Linux amd64元数据诊断程序连同源码、摘要和任务说明传入目标机，只输出指定会话的必要字段。

第一步只读核查：实际宿主执行器路径、Antigravity适配包版本/摘要、三个默认数据目录，以及指定主会话与疑似子会话的数据库行、内部标记、父会话和嵌套深度。程序使用只读SQLite连接，不输出preview、raw_summary、对话正文、钩子命令或凭据。路径和ID保留在部署者的私有任务说明中。

主子关系已有明确证据；下一阶段应核实首次真实转换过程的输入、实际数据根、查询结果/耗时/错误和最终放行决定。仅在旁路hook读取元数据可能错过原转换时序，不能替代实际转换边界的诊断。修改真实hook或触发真实模型任务须单独获得授权，已有开始事件不能被合成输入替代。目标机不安装开发套件，修复构建在开发机完成；既有真实数据的归档或纠正另行确认。

## Antigravity 身份与停止判断

身份类别已明确：本次反馈中的未命名辅助项由宿主父会话标识和嵌套深度证实为一级子会话，没有原生身份别名证据。因此方案收敛为修正子会话过滤，不合并子任务事件到主会话；否则可能用子任务的结束或失败覆盖主会话状态。具体实例报告只留在私有诊断记录。

本机Antigravity App 2.32.1 / WSL Debian原生复现确认：浏览器子会话首两次hook没有父/根身份字段，App数据库中尚无当前ID，随后索引出现一级子关系。已采用本机身份暂存并异步核对，使用现有Bridge内存配额及适配器查询边界；修复后新子任务不进入隔离Hub，主会话正常采集。元数据持续未知不猜身份，等待可由健康查询观察。

同时确认后台子任务结束后不保证追加主会话Stop。正常Stop未完全空闲时登记本轮原生状态观察，新活动和新轮次结束旧观察；明确原生空闲后收尾，原生Stop与观察结果按本机轮次去重，不以空闲时长推断完成。

既有误入条目的处理与新事件过滤分开：保留事件和已读数据，可在明确授权后仅归档已证明的子会话；不删除或重建，不合并到主会话。正式服务、hook或原数据操作仍需明确授权。

停止判断应同时核对原因、是否完全空闲和宿主真实终态：

- 正常模型停止但 `fullyIdle=false`，表示背景任务未全部结束，不能据此直接报完成或因名称不同一律报未知。
- 原生App的ERROR、USER_CANCELED及各类执行限制需要按确切语义映射，不能只识别CLI小写值；终止步骤与自定义hook终止也不能不加区分地当成功。
- 明确错误/取消与后台仍活跃可能同时出现时，依据主轮次真实结束语义处理，不让 `fullyIdle=false` 无条件吞掉失败或取消。
- 未知停止原因、连接失联与后台任务仍运行是不同情况，应保留有解释的状态；不恢复基于空闲超时猜完成的方案。

目标宿主版本与本机静态分析版本可能不同。公开页面和本机较新产物只能形成候选规则，必须以发生问题的目标产物和最小化原生hook字段验证。

## 验收边界

Go、Rust与真实本地服务联调验证不替代目标Agent原生任务及桌面视觉验收。Windows原生关键事件切换、长正文和回到最新已通过隔离演示检查；精确时间边界由回归验证。下一步为候选同提交构建与部署后的实机回归。用户已授权连续推进发布草稿和部署；Git操作仍限于完成本候选所必需的提交与标签，不改写旧公开候选。具体检查命令、版本及结果只维护在[开发记录](development-status.md)。
