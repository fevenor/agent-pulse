# 后续开发计划

本页只维护当前剩余工作及完成条件。需求与运行规则见相应设计、部署文档；实现进度和验证证据见[开发记录](development-status.md)，变更历史见[CHANGELOG](../CHANGELOG.md)。沿用Go服务、Rust与GPUI桌面客户端、Vue管理页面及独立适配包，不扩大技术栈。

## 当前候选与发布边界

当前构建目标为`v0.6.0-rc.4`草稿，增加独立adapter仓库更新、按需同步和ZCode Server Linux接入；Hub/Bridge/Tray需要首次更新，Relay复用`v0.6.0-rc.2`网络协议和版本。前序第二候选草稿与Hub定向更新产物保持。公开推荐为`v0.5.0-rc.4`。候选代码、完整CI、附件摘要、签名仓库及部分真实部署已有验证记录。没有新的源码变更时，不将重复构建作为日常验收前提；发现问题后按实际改动重跑相关检查。

`0.3.8`是新控制接口Antigravity适配包版本，不是产品发行版本。公开候选、取消预发布标识及推广稳定latest是不同动作；只有获得相应明确授权后才执行。未公开候选不能作为匿名默认安装目标，公开版本标签和同版本包内容保持不可变。

## 通讯优化与目标网络验收

整体通讯优化已实现并完成候选交付和可访问实例部署；采用[对象增量与正文缓存方案](communication-optimization-proposal.md)，覆盖Bridge、Tray、Hub、Relay和Web。[流量说明](communication-traffic-assessment.md)定义现行传输和计数口径。剩余工作是全部目标电脑完成同候选升级，并在实际网络记录3小时活动及8小时后台流量；短时应用载荷测量不能代替VPN或运营商账单。保持原失联保护、通知及时性、完整历史及离线已读。

## ZCode Server Linux 接入

接入规则见[ZCode Server说明](adapters.md#zcode-server-的-linux-接入)，实现、WSL及SSH主流程的真实验证见[开发记录](development-status.md)。剩余工作是按使用者确认的发布与部署范围提供新Linux Bridge及同平台签名包，保持既有包不可变、来源身份与公钥不变；未发布包不能作为公开安装目标。权限等待、取消/异常退出、arm64及实际Tray/手机提醒仍按真实验证补齐，不由正常完成、原生提问或子会话过滤推断。

## 适配仓库与按需同步

[更新设计](adapter-repository-update-proposal.md)规定Hub默认每天上海时间02:00检查（可配置或关闭），支持独立GitHub发布和离线导入；Bridge仅启动、setup及手工同步时更新，并联动hook。源码已实施，正式发布、首次Hub/Bridge/Tray部署及真实宿主回归仍待对应授权和验收。新包自带控制入口，普通新增Agent或配置格式不需要核心改版。

## 本候选发布前待确认

| 范围 | 完成条件 | 边界 |
| --- | --- | --- |
| 实际安装及运行 | 已升级Bridge/Tray的来源取得预期适配包installed；真实宿主事件使running更新为相同版本，安装报告无错误 | 离线来源不算安装完成；旧running是最近一次实际回执，不自动表示仍在执行旧包 |
| Antigravity目标环境 | 在原问题宿主版本和WSL执行环境进行新浏览器子任务，确认子任务不成为独立提醒会话；主会话不提前完成、不重复完成，最终状态正确 | 本机新版本复现和隔离回归不能代替原问题环境；既有误入子会话不删除、不合并、不自动标读 |
| 阅读与时间线 | 真实Tray确认前台展开标题连续可见1.5秒标读，切后台/滚出后重新计时；打开历史未读可直接定位；关键事件页不被普通运行记录占满，长正文阅读与新增事件不抢位置 | 自动检查与演示已有证据，日常桌面体验仍由实际使用确认 |
| 多客户端与恢复 | 在本次更新的客户端间确认已读同步，正常断线重连后无未读丢失或明显重复提醒；重启保留配置、主机偏好和缓存 | 不通过批量已读、删除历史或合成事件宣称原生验收完成 |
| 发布操作 | 使用者确认公开候选后，复核构建提交、附件和镜像；公开草稿、更新推荐安装版本与发布说明，再匿名验证下载、摘要和镜像清单 | 不自动取消预发布标识或推广latest；不把发布成功当作全部目标部署完成 |

正式共享仓库应提供该候选已核验的平台包。分批部署使用的临时pins在完整仓库提供相同版本后撤销，仅撤销本轮添加的条目，保留使用者既有选择；不让临时固定阻断后续正常更新。安装版本、最近运行版本和主程序版本分别核对，不以其中一项推断其余全部一致。

## 发布与部署维护要求

- 整体升级使用同候选Hub、Relay、Bridge与Tray；第二候选更换对象增量及Hub/Relay隧道，原RC4 Relay透传首候选的结论不适用。外置签名仓库须同步切换，尚未升级的目标明确列为待办，不能当作已部署。
- 每次共享仓库发布使用递增签名序号，保留原公钥和已分发不可变包；外部仓库覆盖镜像内仓库，更新镜像时不得将客户端已接收的较高序号回退。回滚重新以更高序号发布原包，不能覆盖原序号内容。
- 更新前备份程序、私人配置、适配器选择和一致性数据库，停止Bridge前确认待发为零，包括等待身份核对的事件。程序回滚保留升级期间产生的现行数据，不自动用旧数据库或Tray缓存覆盖新事件和已读；存储结构变化另行明确处理。
- 代码变更仍执行相应Go竞态与静态检查、Node和Rust检查；桌面受影响路径补原生交互验证。ARM镜像的模拟运行不代替ARM真机；当前命令型适配包只承诺已交付的平台。
- 真实账号、模型与手机目标按实际授权使用。手机验收区分接口接受、App收件和系统通知，不把HTTP成功记为实收，不批量重发历史失败任务。

## 继续保留的专项验收

以下项目没有全部完成，按既有优先级逐项补验，不因本候选公开自动变为通过，也不全部重新提升为本次发布阻断：

- **手机与自然模型失败**：新候选的实际手机收件/系统通知，以及自然桌面模型整轮最终失败的端到端体验。已有模拟模型、隔离接收器及字段回归只证明对应链路。
- **Windows桌面场景**：通知点击、悬浮入口与详情偏好、任务唤醒及正常退出、锁屏/全屏、远程桌面、Explorer重启、多屏/DPI、登录自启动及睡眠恢复。各项依据真实记录区分已验范围和剩余组合，短时检查不证明长期稳定。
- **原生Agent覆盖**：Antigravity的其他内部子任务、ACP及异常退出；Qoder交互提问/批准、ZCode提问/权限与异常退出、OpenCode真实模型结束/失败/子任务；Codex自然最终失败及来源受限路径。保留原生能力边界，缺少可靠终态不猜完成。
- **平台与长期运行**：物理多机的持续自动更新、离线恢复、资源表现及ARM真机。来源缺少真实运行回执时保留未确认，不把installed或进程存在当作已加载证明。

各Agent的当前字段、事件与限制以[事件覆盖表](event-coverage.md)为准。当前Windows接入包括ZCode、Codex/ChatGPT本地桌面任务及Antigravity App；WSL任务由发行版自己的Bridge采集。Qoder和OpenCode的Windows终端接入不在当前承诺范围，不再沿用早期“Windows只支持ZCode”的范围描述。

## 不纳入本候选的工作

读取Agent原生已读状态的同步仍不纳入；Hub接受有效运行事件后自动标读旧提醒属于当前已读规则，不新增独立阅读通路。冗余工具活动过滤另行按等待解除和重连核对的必要信号评估，不阻塞本次Hub更新。历史误入子会话的人工归档需另行明确，不作为新事件过滤的修复步骤。手机渠道优先级与失败切换、桌面高级筛选/置顶/别名编辑、批量历史管理、macOS/Linux桌面、完整对话同步、远程回答/批准及客户端自动更新继续后置，不因本次发布临时扩展。
