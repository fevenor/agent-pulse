# 后续开发计划

沿用已确认的 Go 服务、Rust + GPUI 桌面客户端、Vue 管理页面和独立适配包，继续跨平台收尾与部署验收。已完成事项与验证证据见 [开发记录](development-status.md)，本页只维护剩余工作和完成条件。

## 下一阶段：RC 草稿与人工试运行

Tray 的图标、通知分流、主机静默/唤醒、中继发现与展开式时间线已实现，ZCode 正常主会话链路已实测。Hub 默认配置和签名仓库附加流程已实现；先通过同提交的两类 GitHub 工作流生成 RC 草稿，人工运行数日后再决定发布；完整普通用户 Hub 仍需发布者沿用长期密钥签名，按已确认平台范围记录接入证据；详情快捷偏好、唤醒退出、通知分流及悬浮入口四类剩余补验留到 RC 发布后长期运行观察。沿用 Rust + GPUI、便携单入口和内置 Bridge，不扩大为完整桌面客户端。准备和检查入口见 [Windows 开发](windows-development.md)。

桌面改动后执行 `scripts/check/check.ps1 -Tray -Integration`，并对受影响的原生交互进行人工验收。重点保留窗口激活、可见内容自动已读、列表与详情、悬浮入口、Bridge 生命周期和离线重连的既有行为。源码检查通过不替代实际 Windows 桌面验证。

手机渠道字符上限由 Hub 发送阶段处理，无需改写 Tray 正文；桌面继续读取完整事件。联调使用当前源码和产物、隔离配置和测试数据，避免将私人部署状态写入项目文档。

## 1. 验收 Windows 交付与适配包发布

Windows 与 Linux 工作流提供未签名包构建产物和 `hub-base`；正式 Hub RC 需由发布者签名包仓库，再按 [镜像说明](images.md#准备普通用户-hub-rc-镜像) 附加仓库并推送完整 RC 镜像。提交与构建验证范围见 [开发记录](development-status.md)。

- 使用已验证的 Windows 原生适配包和 Linux 包准备正式公用索引，以发布者的私钥签名，再使用 `scripts/release/prepare-hub-release.py` 将公钥和签名包加入匹配的 `hub-base`，构建并发布完整 RC Hub 镜像；临时密钥验证不等于正式发布。
- RC 命令适配包目前支持 Linux amd64 与 Windows amd64；Hub/Relay 的 Linux arm64 镜像不代表 Agent 适配包支持该架构。
- 本轮 Windows 发布与默认配置入口只提供 ZCode；Linux 原有来源不变。ZCode 3.17.2 正常主会话链路和内置 Bridge 已通过；Windows Codex CLI 不构建、不默认探测，也不作为 RC 加载验收门槛。发布时核对本轮公共接入能力与适配包的实际产物，不维护旧接收器版本门槛。保持安装版本、最近运行版本分别展示。
- 后续代码调整继续执行两类 Workflow，桌面交互调整保留 Windows 人工回归。

完成条件是原生便携包在目标主机可运行，正式公用索引能为不同平台选择正确包并取得实际加载回执。构建、签名发布及生产部署分别记录结果。

## 2. 补齐实际 Agent 的剩余边界

使用隔离工作区，避免改写日常 Agent 配置。

- Linux Antigravity：普通直接启动已取得真实模型任务的 hook 与入库证据；继续补 ACP 原生任务 hook、内部子代理及非正常退出的实测。空 ACP 会话没有触发 hook 时，仅记录进程识别和共用入口的测试结果，不声称完整过滤已验收；不恢复包装启动或主会话绑定。
- Linux Qoder：用 DeepSeek-Flash 验证独立包更新后的重新加载与异常退出；使用已经由宿主正常确认可信的专用工作区，不持久关闭信任检查。
- Linux Codex：保持基础 hook 与本地模拟模型回归；等待输入/批准的高级事件继续后置。需要在线测试时串行执行，遵守最多两路并发的限制。
- ZCode：正常主会话开始/继续/完成已验收；异常退出、取消和真实子代理继续验证，不把缺失 Stop 推断为完成。
- Linux OpenCode：常规回归使用不调用模型的真实插件与表单测试；若需要真实模型轮次，使用 build 角色和免费模型。

完成条件是逐个来源记录宿主版本、实际加载版本、已验证事件和剩余限制。某个来源能力不足时保留其边界，继续完成其他来源及服务工作。

## 3. 部署与联合验收

部署顺序为 Hub/Relay → Bridge/Tray → OpenCode 插件。Hub 升级前停止写入并备份数据库，或使用 SQLite 备份能力；回退使用升级前备份，不能将新库直接交给旧程序。

- 在目标环境验证 TLS 反向代理、Relay 公网访问控制、Hub 反向连接和用户 systemd 启停/登录生命周期。部署地址与运行条件落实前，继续使用本地恢复及配置检查。
- 用 Windows 桌面、Linux Agent 与网页共同验证直连/中继回退、离线重连和跨设备已读，确认桌面状态对手机发送的影响。常规回归使用本地 HTTP 接收器，最终实收沿用已有渠道，密钥和原始响应不进入仓库。
- Windows 专项保留实际托盘入口、列表交互、四边悬浮、不同 DPI、可见内容自动已读、锁屏/全屏、远程桌面重连和 Explorer 重启验收；登录自启动、多屏与休眠恢复按用户已确认安排后置。

完成条件是记录目标环境的部署及端到端通知结果，明确仍未验证的平台场景。amd64 上的 arm64 模拟运行不替代 arm64 真机，短时资源采样不替代长期运行。

## 后置范围

手机渠道优先级与失败切换在现有链路稳定后推进；当前多个渠道分别发送的行为保持明确。桌面高级筛选、置顶、别名编辑、人工状态修正备注和批量历史管理继续后置。ZCode 工具等待与非正常退出自动判定继续后置；Codex 高级事件、物理多主机长期更新及 arm64 真机按既有优先级安排。

macOS/Linux 桌面、完整对话同步、远程回答/批准、客户端自动更新和安装向导不纳入本轮。Bridge 改写语言需有实际资源测量和独立选型结论后再讨论。

## Windows 后续接入方向

Windows 优先发挥图形界面优势，后续来源优先调研 ChatGPT Windows 桌面端等图形界面产品的公开事件、扩展或集成能力；Windows Codex CLI 与 ChatGPT Windows 桌面端均为后续规划，本轮 RC 不做支持。未确认具体能力和方案前不实现通用 GUI 抓取、进程监控或会话文件采集，不把无官方入口等同于已经接入。Qoder、Antigravity、OpenCode 的 Windows 终端适配不属于当前计划，不能反向成为本轮发布门槛。

## 实际部署反馈后的收尾

- 不在用户首次明确要求前实现通讯/存储旧版兼容；已撤回接收器最低版本门槛和数据库迁移，只保留当前格式重启、去重及备份恢复。Agent 的补丁、次版本、主版本政策独立执行，补丁变化本身不列为问题。
- Antigravity 已撤回包装启动/绑定要求，直接 CLI 事件正常转换。Bridge 本机接入共用 ACP 判断，显式子/内部元数据另外过滤；普通启动及 ACP 的真实隔离验证和 Windows 系统 API 原生检查分别记录，不把测试输入当实际接入。
- 手机实际恢复接收已经用户确认；本轮只调整正式消息模板并重启 Hub，没有升级正式数据库或重发历史失败记录。继续保持真实接收与接口、源码措施的区别；后续新产物部署和额外测试仍按授权范围执行。
